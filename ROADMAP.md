# Learning Roadmap

This roadmap connects general software engineering knowledge to the practical skills needed for Java backend development. It is a guide, not a rigid deadline-based syllabus.

## Phase 0 — Baseline assessment

**Purpose:** Find out what I already understand so learning starts at the right level.

- [ ] Explain what software engineering means.
- [ ] Distinguish programming from software engineering.
- [ ] Explain the software development life cycle.
- [ ] Describe how a team takes a feature from an idea to production.
- [ ] Explain requirements, design, testing, deployment, and maintenance.
- [ ] Identify areas that need review.

**Completion evidence:** I can explain the basic engineering workflow and identify my knowledge gaps.

## Phase 1 — Software engineering foundations

- Software engineering vs. programming
- Software products and quality attributes
- Software development life cycle (SDLC)
- Software process models: plan-driven, iterative, incremental, and Agile
- Engineering trade-offs: cost, time, scope, quality, and risk
- Technical debt and maintainability
- The difference between a process, a method, a practice, and a tool

**Outcome:** I understand the overall discipline and can explain why software development needs an engineering approach.

## Phase 2 — Professional development workflow

- Git fundamentals and branching
- Commits and meaningful commit messages
- Pull requests and code review
- Issues, tasks, and work tracking
- Branching strategies and collaboration
- Continuous integration basics
- Definition of Done and team conventions

**Outcome:** I understand how developers collaborate safely on a shared codebase.

## Phase 3 — Requirements and analysis

- Stakeholders and business goals
- Functional and non-functional requirements
- User stories and use cases
- Acceptance criteria
- Constraints, assumptions, and scope
- Requirement validation and change management
- Basic modeling: activity, sequence, and domain diagrams

**Outcome:** I can turn a problem into requirements that developers and testers can understand.

## Phase 4 — Design and architecture

- Decomposition and separation of concerns
- Abstraction, encapsulation, and modularity
- Coupling and cohesion
- SOLID principles and their limits
- Layered architecture
- REST API design and HTTP fundamentals
- Error handling and validation
- Design patterns: when they help and when they add unnecessary complexity
- Architecture trade-offs and documentation

**Outcome:** I can explain and evaluate the structure of a maintainable backend application.

## Phase 5 — Java backend engineering

- Modern Java foundations and object-oriented design
- Collections, generics, exceptions, and streams
- Build tools and dependency management
- Maven or Gradle
- Spring Framework and Spring Boot
- Dependency injection
- REST controllers and service layers
- Configuration and environment-specific settings
- Validation, logging, and error responses
- Authentication and authorization fundamentals

**Outcome:** I can understand the components of a typical Java backend and how they work together.

## Phase 6 — Databases and data

- Relational database concepts
- SQL and PostgreSQL
- Tables, keys, constraints, and relationships
- Joins, grouping, and subqueries
- Normalization and data modeling
- Transactions and ACID
- Indexes and query performance
- Java database access and ORM concepts
- Schema changes and migrations

**Outcome:** I can model, query, and safely manage data for backend applications.

## Phase 7 — Quality and testing

- Verification vs. validation
- Unit, integration, and end-to-end testing
- Test cases and test boundaries
- JUnit and mocking concepts
- Regression testing
- Debugging methods
- Code readability and maintainability
- Refactoring and code review
- Static analysis and quality checks

**Outcome:** I can explain how teams gain confidence that software works and remains maintainable.

## Phase 8 — Delivery and operations

- Application packaging and environments
- Build pipelines and CI/CD
- Docker fundamentals
- Deployment concepts
- Environment variables and secrets
- Logs, metrics, and traces
- Monitoring and alerting
- Rollbacks and release strategies

**Outcome:** I understand what happens after code is committed and how a backend service is operated.

## Phase 9 — Security and reliability

- Common web application risks
- Input validation and safe data handling
- Authentication vs. authorization
- Password storage concepts
- Least privilege and secrets management
- Availability, reliability, and resilience
- Timeouts, retries, and failure handling
- Backups and recovery

**Outcome:** I can recognize common risks and explain basic ways to reduce them.

## Phase 10 — Teamwork, communication, and career

- Working with product managers, designers, QA, and other developers
- Asking clear technical questions
- Writing useful documentation
- Explaining technical decisions
- Estimation and prioritization
- Giving and receiving code review feedback
- Backend interview preparation
- Describing projects honestly and clearly

**Outcome:** I can participate more effectively in a professional engineering team and explain my work.

## Phase 11 — Case studies

Apply the knowledge to realistic systems such as:

- A bank account service
- A task management API
- An authentication service
- An online shop
- A booking system

For each case study, consider the problem, stakeholders, requirements, design, data, testing, security, deployment, and trade-offs.

## Priority guide

- **Core:** Software engineering foundations, workflow, requirements, design, Java, SQL, testing, APIs, Git, and security basics.
- **Next:** CI/CD, Docker, observability, performance, and system design.
- **Later:** Advanced distributed systems, complex cloud architecture, and specialized infrastructure.

Do not rush into advanced system design before understanding APIs, databases, testing, and basic application architecture.
