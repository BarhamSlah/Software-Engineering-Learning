# Learning Roadmap

This is a structured course from the learner's current level: beginner with partial foundations. It connects general Software Engineering to Java backend development. It is a sequence, not a deadline.

## Phase 0 — Personal baseline

**Status: Completed as an initial self-assessment; some topics still need confirmation.**

- [x] Recognize that programming is more than typing code.
- [x] Name early SDLC phases.
- [x] Identify banking actions such as deposit and withdrawal as product capabilities.
- [x] Give a simple bug example.
- [x] Recognize basic Git words and the API/waiter analogy.
- [ ] Explain the full SDLC, requirements, software design, testing, deployment, and maintenance confidently.
- [ ] Explain persistence and safe database transactions.

## Phase 1 — Software Engineering foundations (start here)

1. Programming vs. Software Engineering
2. Problem-solving, design, and coding: how they relate
3. What software engineers do and common specializations
4. Software Development Life Cycle (SDLC)
5. Iterative and incremental development; Agile basics
6. Software quality: correctness, security, reliability, usability, maintainability
7. Technical debt and engineering trade-offs

**Outcome:** Explain the whole software lifecycle and why engineering is more than coding.

## Phase 2 — Professional development workflow

1. Git vs. GitHub
2. Repository, working tree, staging, commit
3. Branches and why teams use them
4. Push, pull, fetch, merge
5. Pull Requests (PRs)
6. Code review: approve, request changes, discuss
7. Issues, tasks, and continuous integration basics

**Outcome:** Explain how a change moves safely from a developer's machine into the shared project.

## Phase 3 — Requirements and analysis

1. Stakeholders and user needs
2. Functional requirements
3. Non-functional requirements
4. Scope, assumptions, and constraints
5. User stories and use cases
6. Acceptance criteria
7. Requirement changes and prioritization

**Outcome:** Turn a vague idea into clear requirements that can be designed and tested.

## Phase 4 — Design and architecture

1. UI/UX design vs. software design
2. Data, component, and process design
3. Architecture: the high-level structure
4. Separation of concerns, modularity, cohesion, and coupling
5. Layered backend architecture
6. API design and HTTP basics
7. SOLID and design patterns (after fundamentals)

**Outcome:** Explain how a system is organized and why design is not only colors or screens.

## Phase 5 — Java backend engineering

1. What a backend does
2. Request → controller → service → repository → database
3. Java classes and responsibilities in an application
4. Build tools and dependencies (Maven/Gradle)
5. Spring and Spring Boot purpose
6. Dependency injection
7. Validation, error handling, and logging
8. Authentication and authorization foundations

**Outcome:** Understand the parts of a typical Java backend and how a request is processed.

## Phase 6 — Databases and data

1. Database vs. in-memory data
2. Persistence and relational database basics
3. Tables, rows, columns, primary keys, foreign keys
4. SQL and PostgreSQL
5. Relationships and data modeling
6. Constraints and validation
7. Transactions and ACID
8. Indexes and query performance
9. Java application/database connection

**Outcome:** Explain how data is stored, retrieved, and protected—especially during money transfers.

## Phase 7 — Quality and testing

1. Feature, defect/bug, and expected behavior
2. Why testing is needed
3. Test cases and edge cases
4. Unit, integration, and end-to-end tests
5. Debugging
6. Regression testing
7. Code quality, refactoring, and maintainability
8. Code review and testing together

**Outcome:** Explain how teams gain confidence that software behaves correctly.

## Phase 8 — Delivery and operations

1. Local, test/staging, and production environments
2. Build and package an application
3. What deployment means
4. CI/CD basics
5. Configuration and environment variables
6. Docker fundamentals
7. Logs, metrics, monitoring, and alerts
8. Rollback and release safety

**Outcome:** Explain how software moves from a developer's computer to a live environment and how it is operated.

## Phase 9 — Security and reliability

1. Authentication vs. authorization
2. Input validation and trust boundaries
3. Password storage concepts
4. Secrets and least privilege
5. Common web application risks
6. Reliability, availability, and resilience
7. Timeouts, retries, and safe failure
8. Backups and recovery

**Outcome:** Recognize common risks and explain basic ways to reduce them.

## Phase 10 — Teamwork and career

1. Roles in a software team
2. Working with product, design, QA, and developers
3. Clear technical communication
4. Documentation and decision records
5. Estimation and prioritization
6. Giving and receiving review feedback
7. Explaining projects and preparing for interviews

**Outcome:** Understand how people collaborate and communicate in software teams.

## Phase 11 — Case studies

- Banking account and transfer system
- Task management API
- Authentication service
- Online shop

For each: problem → stakeholders → requirements → design → implementation plan → tests → data → security → deployment → maintenance.

## Priority

**Learn now:** foundations, SDLC, requirements, design, Git workflow, testing basics.

**Learn next:** APIs, backend architecture, PostgreSQL persistence and transactions, deployment basics.

**Learn later:** advanced distributed systems, complex cloud architecture, Kubernetes, and advanced system design.

Do not jump to advanced architecture before understanding the basic lifecycle, APIs, databases, testing, and deployment.
