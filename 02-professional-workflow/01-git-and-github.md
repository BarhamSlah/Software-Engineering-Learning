# Git and GitHub

- **Phase:** 2 — Professional Workflow
- **Status:** Learning

## Simple definition

**Git** is a version control system. It records changes to files so developers can review history and work safely.

**GitHub** is an online platform that hosts Git repositories and adds collaboration tools such as Pull Requests, issue tracking, and code review.

| Git | GitHub |
|---|---|
| A tool for tracking versions and changes | A service for hosting and collaborating on repositories |
| Can work on your computer without internet | Usually accessed online |
| Has commits and branches | Adds Pull Requests, reviews, issues, and project collaboration |

## Simple example

You change the deposit behavior in your Java banking project. Git can record that change as a commit. GitHub can host the repository so another developer can see the change and review it.

## Important words

- **Repository (repo):** Project files and their Git history.
- **Commit:** A recorded snapshot of changes.
- **Branch:** A separate line of work.
- **Push:** Send local commits to a remote repository.
- **Pull:** Fetch remote changes and integrate them into your current branch (in common Git usage).
- **Pull Request:** Ask others to review a proposed change and consider merging it.

## Common misunderstanding

Pushing code to GitHub does not automatically mean the application has been deployed. GitHub stores and collaborates on source code; deployment makes an application available in a runtime environment.

## Key idea

Git tracks changes. GitHub helps people share and review those changes.
