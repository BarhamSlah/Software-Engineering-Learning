# People in a Software Team

- **Phase:** 10 — Teamwork and Career
- **Status:** Learning

## Why are there different roles?

A software product needs more than programming. People help understand the business problem, plan the user experience, build the system, test it, and operate it.

## Common roles

| Role | Main responsibility |
|---|---|
| Customer / stakeholder | Explains needs and business goals |
| Product manager | Helps decide what to build and what matters most |
| Business analyst | Clarifies and documents requirements |
| UI/UX designer | Plans how users interact with the product |
| Software developer/engineer | Designs and builds software |
| QA/test engineer | Checks behavior and helps find defects |
| DevOps/platform engineer | Helps automate delivery and operate systems |
| Security specialist | Helps identify and reduce security risks |

## Example: add a transfer feature

- Product manager clarifies why the feature is needed.
- Analyst helps define rules and requirements.
- Designer plans the user interaction.
- Backend developer builds the transfer logic and API.
- QA checks valid and invalid transfer situations.
- Platform/DevOps engineer helps release and operate the service.

These are simplified examples. In a small company, one person may do several jobs. Job titles and team structures differ between organizations.

## Key idea

Software engineering is teamwork. Different people contribute different skills to deliver one product.
